# Временное восстановление доступа администратора

Этот механизм предназначен для одноразового восстановления существующей учётной записи. Он не создаёт администратора при старте приложения. После успешного восстановления endpoint блокируется постоянным маркером в persistent `data` volume.

## Подготовка в Dokploy

1. Создайте случайный токен локально, не в чате и не в командной строке:

   ```sh
   openssl rand -hex 32
   ```

2. В Dokploy откройте приложение SYA Store → **Environment** и добавьте `ADMIN_RECOVERY_TOKEN` со сгенерированным значением. Не добавляйте префикс `NEXT_PUBLIC_`.
3. Сохраните переменную и выполните deployment новой версии приложения. Само изменение Environment не обновляет учётную запись.
4. Откройте `https://<домен-магазина>/admin/recover`, введите recovery token, новый email и новый пароль (не менее 8 символов), затем отправьте форму. Все поля передаются только в JSON body POST-запроса.
5. После подтверждения откройте `/admin/login` и проверьте вход с новыми данными.

API создаёт резервную копию `data/users.json.backup-<timestamp>` с ограниченными правами, проверяет ровно одну существующую запись администратора, сохраняет её ID и роль и заменяет файл атомарно. Recovery token становится одноразовым; повторные запросы блокируются persistent маркером в `data/.admin-recovery-used`.

## Удаление временного механизма

После проверки входа удалите `ADMIN_RECOVERY_TOKEN` в Dokploy Environment. Затем отдельным cleanup commit удалите страницу `app/admin/recover/page.tsx`, endpoint `app/api/admin/recover/route.ts` и эту инструкцию, после чего разверните cleanup commit. Не удаляйте резервную копию `users.json`.
